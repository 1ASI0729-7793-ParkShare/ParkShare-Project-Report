# Capítulo III: Requirements Specification

## 3.1 User Stories

A partir de las necesidades identificadas durante el proceso de investigación y Needfinding, se definieron las siguientes épicas para organizar las funcionalidades principales de ParkShare. Estas épicas abarcan las necesidades de los conductores, propietarios de espacios y visitantes del Landing Page.

### Épicas

Las siguientes épicas agrupan las principales funcionalidades de ParkShare de acuerdo con las necesidades identificadas para los conductores, propietarios de espacios de estacionamiento y visitantes de la plataforma.

| Epic ID | Título                                                    | Descripción                                                                                                                                                                                                                                                              |
| ------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| EP01    | Gestión de usuarios, identidad y confianza                | Agrupa las funcionalidades relacionadas con el registro, inicio de sesión, gestión de perfiles, registro de vehículos, verificación de identidad y mecanismos orientados a generar confianza entre conductores y propietarios.                                           |
| EP02    | Gestión de espacios de estacionamiento                    | Agrupa las funcionalidades que permiten a los propietarios registrar, publicar, editar y administrar sus espacios de estacionamiento, incluyendo sus características, fotografías, ubicación, disponibilidad y tarifas.                                                  |
| EP03    | Búsqueda y reserva de estacionamientos                    | Agrupa las funcionalidades que permiten a los conductores buscar, filtrar, consultar y reservar espacios de estacionamiento disponibles según su ubicación, fecha, horario, precio y características.                                                                    |
| EP04    | Gestión de reservas, acceso y sesiones de estacionamiento | Agrupa las funcionalidades relacionadas con la administración de reservas, cancelaciones, autorización de acceso al espacio, inicio y finalización de la sesión de estacionamiento y control del uso del espacio reservado.                                              |
| EP05    | Pagos, ingresos, calificaciones y notificaciones          | Agrupa las funcionalidades relacionadas con el pago de reservas, registro y consulta de ingresos de los propietarios, calificaciones entre usuarios y envío de notificaciones sobre eventos importantes de la plataforma.                                                |
| EP06    | Landing Page y comunicación del servicio                  | Agrupa las funcionalidades del sitio web público orientadas a informar a los visitantes sobre ParkShare, comunicar la propuesta de valor para ambos segmentos, presentar las principales características del servicio y dirigir a los usuarios hacia la Web Application. |

### User Stories

A partir de las épicas previamente definidas y de las necesidades identificadas durante el proceso de investigación, se establecieron las siguientes User Stories para ParkShare. Estas historias representan las principales funcionalidades requeridas por conductores, propietarios de espacios de estacionamiento, visitantes del Landing Page y desarrolladores responsables de la integración con el RESTful API.
| Story ID | Título | Descripción | Criterios de Aceptación | Epic ID |
| -------- | ------ | ----------- | ----------------------- | ------- |
| US01 | Registro de usuario | Como usuario nuevo, deseo crear una cuenta indicando mi tipo de usuario, para poder acceder a las funcionalidades correspondientes de ParkShare. | **Escenario 1: Registro válido**<br>**Dado** que el usuario no posee una cuenta y proporciona información válida<br>**Cuando** solicita registrarse indicando su tipo de usuario<br>**Entonces** el sistema registra su cuenta y almacena el rol seleccionado.<br><br>**Escenario 2: Datos ya registrados**<br>**Dado** que existe una cuenta asociada a los datos proporcionados<br>**Cuando** el usuario intenta registrarse nuevamente<br>**Entonces** el sistema rechaza el registro e informa que los datos ya se encuentran asociados a una cuenta. | EP01 |
| US02 | Inicio de sesión | Como usuario registrado, deseo iniciar sesión con mis credenciales, para acceder de forma segura a mi cuenta y funcionalidades. | **Escenario 1: Credenciales válidas**<br>**Dado** que el usuario posee una cuenta registrada<br>**Cuando** proporciona credenciales válidas<br>**Entonces** el sistema autentica al usuario y permite el acceso a su cuenta.<br><br>**Escenario 2: Credenciales incorrectas**<br>**Dado** que el usuario intenta autenticarse<br>**Cuando** proporciona credenciales incorrectas<br>**Entonces** el sistema rechaza la autenticación e informa que las credenciales no son válidas. | EP01 |
| US03 | Verificación de identidad | Como usuario de ParkShare, deseo verificar mi identidad, para generar mayor confianza al interactuar con otros usuarios de la plataforma. | **Escenario 1: Verificación satisfactoria**<br>**Dado** que el usuario proporciona la información requerida para validar su identidad<br>**Cuando** la información es verificada correctamente<br>**Entonces** el sistema registra al usuario como verificado.<br><br>**Escenario 2: Verificación rechazada**<br>**Dado** que el usuario solicita verificar su identidad<br>**Cuando** la información proporcionada no puede ser validada<br>**Entonces** el sistema mantiene la identidad como no verificada e informa el resultado de la validación. | EP01 |
| US04 | Registro de vehículo | Como conductor, deseo registrar los datos de mi vehículo, para utilizarlo al realizar reservas de espacios de estacionamiento. | **Escenario 1: Vehículo válido**<br>**Dado** que el conductor posee una cuenta activa<br>**Cuando** registra los datos válidos de un vehículo<br>**Entonces** el sistema asocia el vehículo con su perfil.<br><br>**Escenario 2: Datos inválidos**<br>**Dado** que el conductor intenta registrar un vehículo<br>**Cuando** proporciona información incompleta o inválida<br>**Entonces** el sistema rechaza el registro del vehículo e informa los datos que deben corregirse. | EP01 |
| US05 | Servicio API de usuarios e identidad | Como Developer, deseo disponer de servicios RESTful para gestionar usuarios, perfiles e identidad, para integrar estas funcionalidades con los clientes de ParkShare. | **Escenario 1: Request válido**<br>**Dado** que un cliente autorizado envía una solicitud válida al servicio<br>**Cuando** el API procesa la operación solicitada<br>**Entonces** devuelve una respuesta exitosa con los datos correspondientes.<br><br>**Escenario 2: Request con datos inválidos**<br>**Dado** que un cliente autorizado envía datos inválidos o incompletos<br>**Cuando** el API procesa la solicitud<br>**Entonces** devuelve una respuesta de error indicando la causa y no modifica los recursos existentes.<br><br>**Escenario 3: Cliente no autorizado**<br>**Dado** que un cliente no posee autorización para realizar la operación solicitada<br>**Cuando** intenta acceder al servicio<br>**Entonces** el API rechaza la operación sin exponer ni modificar información del usuario. | EP01 |
| US06 | Publicación de espacio de estacionamiento | Como propietario, deseo registrar y publicar un espacio de estacionamiento, para ofrecerlo temporalmente a conductores interesados. | **Escenario 1: Publicación válida**<br>**Dado** que el propietario posee un espacio disponible y proporciona la información requerida<br>**Cuando** registra el espacio<br>**Entonces** el sistema crea la publicación asociada al propietario.<br><br>**Escenario 2: Información incompleta**<br>**Dado** que el propietario intenta registrar un espacio<br>**Cuando** falta información obligatoria<br>**Entonces** el sistema no publica el espacio e informa qué información debe completarse. | EP02 |
| US07 | Edición de espacio publicado | Como propietario, deseo modificar la información de mis espacios publicados, para mantener actualizados sus datos y características. | **Escenario 1: Actualización válida**<br>**Dado** que el propietario posee una publicación existente<br>**Cuando** modifica información válida del espacio<br>**Entonces** el sistema actualiza los datos de la publicación.<br><br>**Escenario 2: Espacio no perteneciente al propietario**<br>**Dado** que un propietario intenta modificar una publicación ajena<br>**Cuando** solicita guardar los cambios<br>**Entonces** el sistema rechaza la operación y mantiene la información existente. | EP02 |
| US08 | Configuración de disponibilidad | Como propietario, deseo establecer los días y horarios en los que mi espacio está disponible, para evitar conflictos con mi propio uso del estacionamiento. | **Escenario 1: Periodo de disponibilidad válido**<br>**Dado** que el propietario posee un espacio publicado<br>**Cuando** establece un periodo cuya hora de inicio es anterior a la hora de finalización<br>**Entonces** el sistema registra el periodo como disponible para reservas.<br><br>**Escenario 2: Periodo temporal inválido**<br>**Dado** que el propietario configura la disponibilidad de su espacio<br>**Cuando** establece una hora de finalización igual o anterior a la hora de inicio<br>**Entonces** el sistema rechaza el periodo e informa que el rango horario no es válido.<br><br>**Escenario 3: Conflicto con reserva confirmada**<br>**Dado** que existe una reserva confirmada dentro del periodo seleccionado<br>**Cuando** el propietario intenta marcar dicho periodo como no disponible<br>**Entonces** el sistema conserva la disponibilidad necesaria para la reserva confirmada e informa el conflicto. | EP02 |
| US09 | Configuración de tarifa | Como propietario, deseo establecer la tarifa de uso de mi espacio, para determinar cuánto cobraré por las reservas realizadas. | **Escenario 1: Tarifa válida**<br>**Dado** que el propietario administra un espacio publicado<br>**Cuando** establece una tarifa válida<br>**Entonces** el sistema registra la tarifa para futuras reservas.<br><br>**Escenario 2: Tarifa inválida**<br>**Dado** que el propietario configura una tarifa<br>**Cuando** el valor no cumple las reglas establecidas<br>**Entonces** el sistema rechaza la tarifa e informa que debe ingresar un valor válido. | EP02 |
| US10 | Servicio API de espacios de estacionamiento | Como Developer, deseo disponer de servicios RESTful para registrar, consultar y actualizar espacios de estacionamiento, para integrar su gestión con la Web Application. | **Escenario 1: Operación válida**<br>**Dado** que el API recibe una solicitud autorizada con datos válidos<br>**Cuando** procesa una operación sobre un espacio<br>**Entonces** devuelve una respuesta exitosa con la información actualizada.<br><br>**Escenario 2: Datos inválidos**<br>**Dado** que un cliente autorizado envía información que no cumple las reglas del recurso<br>**Cuando** el API procesa la solicitud<br>**Entonces** devuelve una respuesta de error y no modifica el espacio.<br><br>**Escenario 3: Operación no autorizada**<br>**Dado** que el cliente no posee permisos para modificar el espacio solicitado<br>**Cuando** intenta realizar la operación<br>**Entonces** el API rechaza la solicitud y conserva la información existente. | EP02 |
| US11 | Búsqueda de estacionamientos por ubicación | Como conductor, deseo buscar espacios de estacionamiento cercanos a mi destino, para reducir el tiempo dedicado a encontrar dónde estacionar. | **Escenario 1: Existen espacios disponibles**<br>**Dado** que el conductor indica una ubicación y periodo requerido<br>**Cuando** realiza la búsqueda<br>**Entonces** el sistema proporciona los espacios disponibles próximos a la ubicación indicada.<br><br>**Escenario 2: No existen espacios disponibles**<br>**Dado** que el conductor realiza una búsqueda<br>**Cuando** no existen espacios que cumplan las condiciones solicitadas<br>**Entonces** el sistema informa que no se encontraron espacios disponibles. | EP03 |
| US12 | Filtrado de estacionamientos | Como conductor, deseo filtrar los espacios disponibles según mis necesidades, para identificar alternativas adecuadas con mayor rapidez. | **Escenario 1: Coincidencias con los filtros**<br>**Dado** que existen espacios disponibles<br>**Cuando** el conductor aplica criterios de precio, horario o características<br>**Entonces** el sistema proporciona únicamente los espacios que cumplen dichos criterios.<br><br>**Escenario 2: Sin coincidencias**<br>**Dado** que el conductor ha establecido filtros<br>**Cuando** ningún espacio cumple todos los criterios<br>**Entonces** el sistema informa que no existen resultados que coincidan con la búsqueda. | EP03 |
| US13 | Consulta de información del estacionamiento | Como conductor, deseo consultar las características de un espacio de estacionamiento, para determinar si satisface mis necesidades antes de reservarlo. | **Escenario 1: Espacio disponible**<br>**Dado** que el conductor consulta un espacio registrado<br>**Cuando** solicita conocer sus detalles<br>**Entonces** el sistema proporciona su ubicación, tarifa, disponibilidad y características registradas.<br><br>**Escenario 2: Espacio no disponible**<br>**Dado** que el espacio seleccionado ya no se encuentra disponible<br>**Cuando** el conductor consulta su información<br>**Entonces** el sistema informa su estado actual y evita que sea reservado durante dicho periodo. | EP03 |
| US14 | Consulta de disponibilidad por fecha y hora | Como conductor, deseo verificar la disponibilidad de un estacionamiento para una fecha y horario determinados, para evitar solicitar un periodo que ya se encuentra ocupado. | **Escenario 1: Periodo disponible**<br>**Dado** que el espacio no posee reservas que se superpongan con el periodo solicitado<br>**Cuando** el conductor consulta su disponibilidad<br>**Entonces** el sistema informa que el periodo está disponible.<br><br>**Escenario 2: Superposición con una reserva**<br>**Dado** que existe una reserva confirmada que se superpone total o parcialmente con el periodo solicitado<br>**Cuando** el conductor consulta la disponibilidad<br>**Entonces** el sistema informa que el periodo no se encuentra disponible.<br><br>**Escenario 3: Periodo de consulta inválido**<br>**Dado** que el conductor desea consultar la disponibilidad<br>**Cuando** indica una hora de finalización igual o anterior a la hora de inicio<br>**Entonces** el sistema rechaza la consulta e informa que el periodo ingresado no es válido. | EP03 |
| US15 | Solicitud de reserva | Como conductor, deseo solicitar la reserva de un espacio disponible, para asegurar un estacionamiento durante el periodo que necesito. | **Escenario 1: Solicitud válida**<br>**Dado** que el espacio se encuentra disponible durante el periodo solicitado<br>**Cuando** el conductor realiza la solicitud de reserva<br>**Entonces** el sistema vuelve a validar la disponibilidad y registra la solicitud.<br><br>**Escenario 2: Disponibilidad modificada antes de la solicitud**<br>**Dado** que el espacio aparecía disponible al momento de ser consultado<br>**Cuando** antes de registrar la solicitud el periodo deja de estar disponible<br>**Entonces** el sistema rechaza la solicitud e informa que la disponibilidad ha cambiado. | EP03 |
| US16 | Servicio API de búsqueda y reservas | Como Developer, deseo disponer de servicios RESTful para consultar disponibilidad y gestionar solicitudes de reserva, para permitir la integración de estas operaciones con los clientes de ParkShare. | **Escenario 1: Consulta o reserva válida**<br>**Dado** que el API recibe una solicitud válida<br>**Cuando** procesa una búsqueda o reserva<br>**Entonces** devuelve una respuesta exitosa con los datos correspondientes.<br><br>**Escenario 2: Conflicto de disponibilidad**<br>**Dado** que el API recibe una solicitud de reserva para un periodo ocupado<br>**Cuando** procesa la operación<br>**Entonces** devuelve una respuesta de conflicto y no crea la reserva. | EP03 |
| US17 | Confirmación de solicitud de reserva | Como propietario, deseo revisar y confirmar solicitudes de reserva, para decidir quién puede utilizar mi espacio de estacionamiento. | **Escenario 1: Reserva aceptada**<br>**Dado** que existe una solicitud pendiente y el periodo continúa disponible<br>**Cuando** el propietario confirma la solicitud<br>**Entonces** el sistema cambia la reserva a estado confirmado y bloquea el periodo correspondiente.<br><br>**Escenario 2: Reserva rechazada**<br>**Dado** que existe una solicitud pendiente<br>**Cuando** el propietario decide rechazarla<br>**Entonces** el sistema registra el rechazo y mantiene disponible el periodo correspondiente.<br><br>**Escenario 3: Periodo confirmado por otra solicitud**<br>**Dado** que existen solicitudes pendientes que se superponen para un mismo espacio<br>**Cuando** una de ellas ya ha sido confirmada y se intenta confirmar otra para el mismo periodo<br>**Entonces** el sistema rechaza la segunda confirmación y conserva la reserva confirmada previamente. | EP04 |
| US18 | Cancelación de reserva | Como usuario con una reserva, deseo cancelarla cuando no pueda cumplirla, para liberar el espacio y gestionar correctamente la reserva. | **Escenario 1: Cancelación antes del inicio de la reserva**<br>**Dado** que existe una reserva activa cuya sesión de estacionamiento aún no ha comenzado<br>**Cuando** el usuario solicita cancelarla dentro de las condiciones permitidas<br>**Entonces** el sistema cancela la reserva y libera el periodo correspondiente.<br><br>**Escenario 2: Cancelación de una reserva pagada**<br>**Dado** que la reserva posee un pago completado y todavía puede ser cancelada<br>**Cuando** el usuario solicita la cancelación<br>**Entonces** el sistema registra la cancelación y aplica la regla de reembolso o penalización definida para la reserva.<br><br>**Escenario 3: Reserva cuya sesión ya comenzó**<br>**Dado** que la sesión de estacionamiento asociada a la reserva ya se encuentra iniciada<br>**Cuando** el usuario intenta cancelar la reserva<br>**Entonces** el sistema rechaza la cancelación e informa que la reserva ya se encuentra en ejecución. | EP04 |
| US19 | Generación de pase de acceso | Como conductor con una reserva confirmada, deseo disponer de una autorización de acceso asociada a mi reserva, para ingresar al espacio durante el periodo autorizado. | **Escenario 1: Acceso válido**<br>**Dado** que el conductor posee una reserva confirmada y vigente<br>**Cuando** valida su autorización dentro del periodo permitido<br>**Entonces** el sistema reconoce la autorización como válida.<br><br>**Escenario 2: Acceso fuera del periodo autorizado**<br>**Dado** que la reserva aún no ha iniciado o su periodo ya finalizó<br>**Cuando** se intenta validar el acceso<br>**Entonces** el sistema rechaza la autorización.<br><br>**Escenario 3: Reserva cancelada o no confirmada**<br>**Dado** que la reserva asociada al pase se encuentra cancelada o no está confirmada<br>**Cuando** el conductor intenta validar el acceso<br>**Entonces** el sistema rechaza la autorización. | EP04 |
| US20 | Gestión de sesión de estacionamiento | Como conductor, deseo registrar el inicio y finalización del uso del estacionamiento, para mantener constancia del periodo real de ocupación del espacio. | **Escenario 1: Inicio de sesión válido**<br>**Dado** que el conductor posee una reserva vigente, confirmada y con acceso autorizado<br>**Cuando** ingresa al espacio reservado<br>**Entonces** el sistema registra el inicio de la sesión de estacionamiento.<br><br>**Escenario 2: Inicio duplicado**<br>**Dado** que la reserva ya posee una sesión de estacionamiento activa<br>**Cuando** se intenta registrar nuevamente el ingreso<br>**Entonces** el sistema rechaza el nuevo inicio y mantiene la sesión existente.<br><br>**Escenario 3: Finalización de sesión**<br>**Dado** que existe una sesión de estacionamiento activa<br>**Cuando** se registra la salida del vehículo<br>**Entonces** el sistema finaliza la sesión y actualiza el estado del espacio.<br><br>**Escenario 4: Finalización sin sesión activa**<br>**Dado** que la reserva no posee una sesión de estacionamiento activa<br>**Cuando** se intenta registrar una salida<br>**Entonces** el sistema rechaza la operación y no modifica el estado del espacio. | EP04 |
| US21 | Servicio API de acceso y sesiones | Como Developer, deseo disponer de servicios RESTful para validar accesos y administrar sesiones de estacionamiento, para integrar el flujo de entrada y salida con ParkShare. | **Escenario 1: Solicitud válida**<br>**Dado** que el API recibe una autorización vigente<br>**Cuando** procesa una operación de acceso o sesión<br>**Entonces** devuelve una respuesta exitosa y registra el evento correspondiente.<br><br>**Escenario 2: Autorización inválida**<br>**Dado** que la solicitud contiene una autorización vencida o no válida<br>**Cuando** el API procesa la operación<br>**Entonces** rechaza la solicitud y devuelve la respuesta de error correspondiente. | EP04 |
| US22 | Pago de reserva | Como conductor, deseo pagar el importe correspondiente a mi reserva, para completar la contratación del espacio de estacionamiento. | **Escenario 1: Pago aprobado**<br>**Dado** que existe una reserva pendiente de pago<br>**Cuando** la operación de pago es aprobada<br>**Entonces** el sistema registra el pago como completado y lo asocia con la reserva.<br><br>**Escenario 2: Pago rechazado**<br>**Dado** que existe una reserva pendiente de pago<br>**Cuando** la operación no es aprobada<br>**Entonces** el sistema registra el intento como fallido y mantiene pendiente el pago de la reserva.<br><br>**Escenario 3: Reserva previamente pagada**<br>**Dado** que la reserva ya posee un pago completado<br>**Cuando** el conductor intenta realizar nuevamente el pago de la misma reserva<br>**Entonces** el sistema no genera un segundo cobro e informa que la reserva ya se encuentra pagada. | EP05 |
| US23 | Consulta de ingresos del propietario | Como propietario, deseo consultar los ingresos generados por mis espacios, para conocer el rendimiento económico obtenido mediante ParkShare. | **Escenario 1: Existen ingresos registrados**<br>**Dado** que el propietario ha completado reservas pagadas<br>**Cuando** consulta sus ingresos<br>**Entonces** el sistema proporciona los montos generados por las reservas correspondientes.<br><br>**Escenario 2: No existen ingresos**<br>**Dado** que el propietario aún no posee reservas pagadas<br>**Cuando** consulta sus ingresos<br>**Entonces** el sistema informa que no existen ingresos registrados para el periodo consultado. | EP05 |
| US24 | Calificación después de una reserva | Como usuario de ParkShare, deseo calificar mi experiencia después de una reserva completada, para contribuir a la reputación y confianza de otros usuarios. | **Escenario 1: Reserva completada**<br>**Dado** que el usuario participó en una reserva finalizada<br>**Cuando** registra una calificación válida<br>**Entonces** el sistema almacena la valoración asociada a la experiencia correspondiente.<br><br>**Escenario 2: Reserva no completada**<br>**Dado** que el usuario no posee una reserva finalizada con la otra parte<br>**Cuando** intenta registrar una calificación<br>**Entonces** el sistema rechaza la valoración. | EP05 |
| US25 | Recepción de notificaciones | Como usuario de ParkShare, deseo recibir notificaciones sobre eventos importantes de mis reservas, para mantenerme informado sobre cambios que requieran mi atención. | **Escenario 1: Cambio relevante en una reserva**<br>**Dado** que ocurre una confirmación, cancelación o modificación relevante<br>**Cuando** el sistema registra el evento<br>**Entonces** genera una notificación para los usuarios involucrados.<br><br>**Escenario 2: Resultado de pago**<br>**Dado** que se procesa un pago relacionado con una reserva<br>**Cuando** se obtiene el resultado de la operación<br>**Entonces** el sistema genera una notificación informando el estado del pago. | EP05 |
| US26 | Servicio API de pagos, reputación y notificaciones | Como Developer, deseo disponer de servicios RESTful para gestionar pagos, calificaciones y notificaciones, para integrar estas funcionalidades con los distintos clientes de ParkShare. | **Escenario 1: Operación válida**<br>**Dado** que el API recibe una solicitud autorizada que cumple las reglas del negocio<br>**Cuando** procesa la operación solicitada<br>**Entonces** devuelve una respuesta exitosa y registra la información correspondiente.<br><br>**Escenario 2: Operación que incumple reglas del negocio**<br>**Dado** que un cliente autorizado envía una solicitud con información inválida o inconsistente<br>**Cuando** el API procesa la operación<br>**Entonces** devuelve una respuesta de error y no registra la operación como completada.<br><br>**Escenario 3: Solicitud no autorizada**<br>**Dado** que el cliente no posee autorización para realizar la operación<br>**Cuando** intenta acceder al recurso<br>**Entonces** el API rechaza la solicitud sin modificar la información existente. | EP05 |
